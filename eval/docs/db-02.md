# Database Transactions and Rollback

A transaction groups several statements into one unit of work. It either commits all changes or rolls back none of them, which keeps the database consistent after a failure.

The isolation level controls what one transaction can see of another. Read committed prevents dirty reads, while serializable avoids most anomalies at the cost of throughput.

Always release connections and end transactions explicitly. A long running transaction holds locks and blocks other writers, so keep the critical section small.
